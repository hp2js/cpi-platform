## Environment and reproduction

Node 24.21.0, pnpm 10.32.0; local PostgreSQL, Redis and MinIO. API integration tests start the compiled Nest application against a separate `_test` database, Redis database 15 and temporary object prefixes. Browser tests use Chromium against the running development stack at `127.0.0.1:5180`, backed by the real API. They reset that local demo's synthetic data before each test. Do not run them against a shared or production environment. Unit tests of `apps/web/src/mocks` exercise the mock implementation and are identified separately.

Run from the repository root with the pinned Node/pnpm versions and the local services running:

```sh
pnpm check
pnpm test:integration
pnpm test:reconciliation
pnpm exec playwright test --reporter=json > artifacts/acceptance-browser.json
```

Create `artifacts/` before redirecting browser output. The focused component/replay check is:

```sh
pnpm --filter @cpi/api exec env INTEGRATION=1 vitest run src/simulation/simulation.int.test.ts --no-file-parallelism --test-timeout=30000
```

The focused command needs the API/contracts builds from `pnpm check`. Do not run two API integration suites simultaneously: they share the test database. Browser fixtures use a different database but replace the active local demo state. Machine-readable execution results are in [results.json](results.json). Test paths below are relative to `apps/api/src/`, unless prefixed with `e2e/` or `apps/web/`. Each named test contains the executable steps, fixture construction and assertions.
