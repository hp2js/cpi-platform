# PRD coverage

Scope: the persisted API (`apps/api`, default) and `apps/web` · Source: PRD v1.1 (`docs/HP2JS — Adili-V3-Track-2-PRD.md`) · Checked: 4 October 2026

How each functional requirement and mandatory scenario is met and what checks it. **API tests** are the integration tests in `apps/api/src` (`*.int.test.ts`), run in CI against PostgreSQL, Redis and MinIO; they are the authoritative check. **Web and mock tests** are `apps/web/src/mocks/*.test.ts` (the same rules in the mock used for unit tests and offline development) and `e2e/*.spec.ts` (browser journeys, which CI runs against the persisted API). Shared rules in `packages/contracts/src/domain` have their own unit tests. Results of the latest full run are in [verification-results.md](verification-results.md); endpoints are in [api-handover.md](api-handover.md).

## Not built, and why

| Procedures as an enforced prerequisite                        | §10.1            | A prerequisite profile shows procedures as met or not met with no points; nothing is blocked by it. The PRD keeps this structure as a reference, not an operational profile.                                                                                                                  |
| Full-text search, extra channels                              | §6.2             | P1 or optional. The optional AI evidence assistant (§14) is built; see [assistant.md](assistant.md) for its boundaries, evaluation and what is not yet run.                                                                                                                                   |
| Performance and scale rehearsal                               | §4.2             | Not measured.                                                                                                                                                                                                                                                                                 |
| eCitizen sign-in, per-IP throttling, TLS and hosted secrets   | §13              | Local accounts are built and tested: scrypt hashes, an HttpOnly session cookie, per-email lockout and emailed sign-in codes ([platform-contracts.md](platform-contracts.md)). eCitizen needs an agreement and OpenID Connect credentials; per-IP throttling and TLS belong to a hosted proxy. |
| Malware scanning, quarantine and retention for real documents | §9.2, §13        | Uploads are refused outside demo mode until `REAL_DOCUMENT_UPLOADS` records that these are approved; the structural checks are not antivirus scanning ([storage.md](storage.md)).                                                                                                             |
| A summary of what a clock advance did                         | FR14 (usability) | The email sink and audit log show it; there is no summary on the Simulation page.                                                                                                                                                                                                             |
| Onboarded institutions across simulation runs                 | FR14             | “Start a new run” restores the seeded fixture set (eight institutions); onboarding is repeated per run. Scoring profiles carry over; the calendar returns to its seeded defaults ([simulation.md](simulation.md)).                                                                            |

## Not verified by automated checks

Passing tests do not establish these; each needs its own evidence before it is claimed.

- **Practitioner validation** (PRD §4.2, HP2-33): only internal walkthroughs have run ([frontend-verification.md](frontend-verification.md), [usability](usability/README.md)).
- **Full accessibility conformance**: axe checks about 30 screens and keyboard journeys run, but screen readers, 400% zoom, text spacing and forced colours have not been tested; this is not a WCAG 2.2 conformance claim.
- **AT23** (keyboard journey) is checked in the browser only; it has no API counterpart.
- **Readable evidence in the scripted year**: the scenario's report evidence passes the upload checks but is not a readable document, so the evidence-to-decision walkthrough cannot open it.
- **Hosted operation**: TLS, hosted secrets, backups and restore, and performance at scale; only the local stack and the production images are exercised.
- **PDF content** inside compressed object streams is not inspected by the upload checks.
